1.Explica la diferencia entre Git y GitHub. R: Git es un control de proyecto locales y GitHub es un control de proyectos pero en la nube y de mas facil acceso para cualquier persona.
2. Explica para qué sirve .gitignore. R: Para que GitHub y git ignore esos archivo a la hora de ponerlos en el repositorio.
3. Explica por qué .venv no debe almacenarse normalmente en GitHub. Porque puede tener problemas con las versiones de python o del lenguaje de programación con el de las otras personas.
4. Explica para qué sirve requirements.txt. R: Para ver las dependencias requeridas para ese proyecto
5. Explica la diferencia entre Stage, Commit y Push. R: El Stage Marca qué cambios entrarán en el próximo commit. El commit Congela esos cambios como snapshot con hash, autor y mensaje. Push sube los commits locales a la nube "GitHub"
6. Explica por qué un repositorio puede tener varios commits antes de realizar un push. R: El commit es una operación local: el repositorio local es una copia completa e independiente, así quepuedo generar varios commits sin conexión y sin que GitHub se entere. Hasta que no hago push, esoscommits solo existen en mi máquina; el push es el que los envía todos juntos al remoto y actualiza larama.
